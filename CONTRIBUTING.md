# Contributing

## Local setup

```sh
npm install
npm run dev      # http://localhost:4321/oss/hokusai/ (English) and /oss/hokusai/uk/ (Ukrainian)
```

`npm run check` runs everything CI runs: translation parity, public-API coverage, the production build, and checks of the built site.

## Languages

English (root, `src/content/docs/`) and Ukrainian (`src/content/docs/uk/`) are both part of every release. A page exists in both languages, at the same relative path, with the same `pageId`.

- Routes: English stays at `/oss/hokusai/…`; Ukrainian is at `/oss/hokusai/uk/…`. The language switch keeps the current page and `#anchor`; nothing redirects by browser language or IP.
- Terminology: see [docs/glossary.md](docs/glossary.md). Code, API names, commands and paths are never translated.
- Shared material (code samples, fixtures, generated images) is reused by both editions; translate prose, tables, labels, captions and alt text only.

### Add a page

1. Create the English page with `pageId` (stable, language-independent, e.g. `guide.resize`) and add it to the sidebar in `astro.config.mjs`.
2. Create `uk/<same path>` with the same `pageId` and a translated `title`/`description`.
3. Give every Ukrainian heading the English anchor so links and the language switch keep working:
   `## Встановлення пакета {#install-the-package}`. (In `.mdx`, write `\{#id}`.) The English anchor is the heading text slugified: lowercase, punctuation removed, spaces to hyphens.
4. Link to the Ukrainian version of other pages (`/oss/hokusai/uk/...`), not the English one.
5. Run `npm run i18n:stamp` to record which English revision the translation matches.

### Change a page

Edit the English page, then update the Ukrainian page and run `npm run i18n:stamp`. `npm run i18n:check` fails while a translation's recorded revision (`translatedFrom`) differs from the English file, so a change can't be forgotten. For a work-in-progress translation add `translationStatus: draft` to the Ukrainian page: it only warns during development, and `npm run i18n:check -- --release` rejects it.

### What CI checks

`i18n:check` (every English page has a Ukrainian pair with a matching `pageId` and a current `translatedFrom`) and `check:dist` after the build: both languages exist for every route, `<html lang>`, canonical and `hreflang` alternates, sitemap entries, identical heading anchors in both languages, and that every internal link and anchor resolves.

## Examples and results

Every code block and every result image on the site comes from `examples/`, a SwiftPM package that runs the **documented release** of Hokusai (needs `brew install vips cairo pango pkg-config` on macOS; Linux needs libvips 8.16+, see `examples/docker`).

```sh
cd examples && swift run DocsExamples run            # run everything, write ../public/generated
swift run DocsExamples run resize                    # only examples whose id starts with "resize"
swift run DocsExamples fixtures                      # regenerate the fixtures (rarely needed)
npm run examples:snippets                            # refresh src/generated/snippets.json
```

To add an example: write an `Example("family.name") { … }` in `examples/Sources/DocsExamples/Examples/`, put the code the page should show between `// snippet: family.name` and `// endsnippet` (plain relative file names; fixtures are copied next to it), list it in `allExamples`, run it, and use it in a page:

```mdx
<Example id="family.name" results={[{ file: 'out.webp', label: '…', alt: '…' }]} />
```

Only the `label` and `alt` are translated; code, images and the measured size caption are shared by both languages. Write facts you observed (dimensions, byte counts, error messages) from the example's printed output, not from memory. Commit `public/generated` and `src/generated/snippets.json`; CI reruns the examples on macOS and fails if a result's format or dimensions differ from the committed manifest. Pages that use components are `.mdx` (write `\{#anchor}` there; in `.md` it is `{#anchor}`).

## Design

The look follows the Hokusai logo: its pale-sky panel, the black and white swallows and their vermillion throats, with **seigaiha** (the traditional Japanese wave pattern) as the texture. Tokens are in `src/theme/tokens.css`, generated by `python3 scripts/gen-theme-tokens.py` (edit the script, not the CSS); the Starlight mapping, header, hero, sidebar and print-style result frames are in `src/theme/starlight.css` and `src/components/Example.astro`.

- Palette: sky `#a8e1fb`, vermillion `#c8321f` (light) / `#ee5a43` (dark), ink `#12181f`; a deep indigo-black for dark mode. Vermillion marks what is active or important (the version seal, the current page, section seals); sky is the brand surface (hero, language switch, the swallow's badge).
- Type: Comfortaa (Latin only) for headings, close to the geometric wordmark; Nunito for Cyrillic headings; Inter for text; IBM Plex Mono for code. Comfortaa's Cyrillic is deliberately not used.
- Keep both themes legible: the logo always sits on its sky panel, never directly on dark.
