Hokusai використовує незмінні конвеєри `Hokusai` та асинхронні завершальні операції виводу. Ця сторінка зіставляє адаптерний API 0.x з поточним і перелічує зміни поведінки між релізами 2.x.

## З 0.x {#from-0x}

| Адаптерний API 0.x | Поточний конвеєрний API |
| --- | --- |
| `Hokusai.image(from: path)` | `Hokusai(url: URL(fileURLWithPath: path))` |
| `Hokusai.image(from: data)` | `Hokusai(data: data)` |
| `image.resize(...).toFile(path)` | `try await pipeline.resize(...).write(to: URL(...))` |
| `image.crop(...)` | `pipeline.extract(x:y:width:height:)` |
| `image.toBuffer(...)` | Оберіть кодувальник, потім `try await .data()` |

### Правила міграції {#migration-rules}

1. Замініть адаптери завантажених зображень значенням `Hokusai`, створеним із `Data` або файлового `URL`.
2. Будуйте перетворення без `await`; перетворене значення все ще є рецептом.
3. Очікуйте (`await`) лише завершальні операції: `data()`, `write(to:)`, `writeChunks`, `raw` і `metadata()`.
4. Продукт сумісності `HokusaiLegacy` не входить до пакетів 2.x.

## У межах 2.x {#within-2x}

- **2.1.0:** `clahe` вирівнює світлоту й зберігає колір, тож кольорові результати відрізняються від ранніх релізів. `write(to:)` і CLI відмовляються записувати у файл, який читає конвеєр; запишіть в інший файл і замініть оригінал після цього.
- **2.2.0:** команди `resize`, `thumbnail`, `convert`, `rotate`, `crop` і `text` застарілі на користь `hokusai run` і будуть вилучені в наступному мажорному релізі. Їхні значення за замовчуванням тепер збігаються з бібліотекою: `resize` вписує з `cover` (було `inside`), а текст має 24 пункти й чорний колір.
- **Метадані:** вивід тепер за замовчуванням зберігає профіль ICC, орієнтацію та щільність і вилучає EXIF, XMP, IPTC і коментарі; ранні версії вилучали все.

Повний перелік дивіться в [журналі змін](/oss/hokusai/uk/changelog).
