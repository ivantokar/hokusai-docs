`HokusaiPDF` — це окремий продукт для **векторних** PDF-документів. На відміну від растрового кодувальника `pdf()`, він малює текст, фігури й градієнти як вміст PDF: текст лишається виділюваним і придатним до пошуку, фігури лишаються чіткими за будь-якого масштабу, а зображення на сторінці вбудовуються як растри, підготовлені звичайними конвеєрами Hokusai. Потрібна **Pango 1.44 або новіша**; продукту `Hokusai` вона не потрібна.

```swift
// Package.swift: додайте продукт до цілі, що створює PDF
.product(name: "HokusaiPDF", package: "hokusai")
```

## Модель \{#model}
`VectorPage` — це **незмінне значення**: кожен метод повертає нову сторінку з ще одним елементом, намальованим поверх попередніх. Нічого не відтворюється, доки не записано `VectorDocument`, а хибні значення відхиляються під час додавання елемента.

| Складник | API |
| --- | --- |
| Сторінка | `VectorPage(size:)` з `.a4(_)`, `.letter(_)` (типово книжкова) або `.points(width:height:)` (`1…14 400`). Початок координат — **лівий верхній кут**, одиниці — пункти (1/72 дюйма). |
| Тло | `.background(_ paint: VectorPaint)`: `.color(Color)` або `.linearGradient(from:to:angle:)`. |
| Прямокутник | `.rectangle(_ frame:fill:stroke:cornerRadius:)`; потрібні заливка, обведення або обоє. |
| Лінія | `.line(from:to:stroke:)` з `VectorStroke(color:width:)` (ширина `0…1000`, більша за нуль). |
| Зображення | `.image(_ pipeline:frame:fit:opacity:)`; `fit` — `.contain`, `.cover` або `.fill`. |
| Текст | `.text(_ content:at:width:style:)`; `TextContent` звичайний або з розміткою Pango. |
| Стиль | `VectorTextStyle(family:size:weight:italic:color:alignment:wrap:lineSpacing:)`; насиченість від `.thin` до `.black`; вирівнювання `.leading`, `.center`, `.trailing`, `.justified`; перенос `.word`, `.character`, `.wordThenCharacter`. |
| Документ | `VectorDocument(pages:metadata:)` або `VectorDocument(_ page:metadata:)`; `data()` і `write(to:)`. |

Друга сторінка (заокруглений темно-синій заголовок, лінія й абзац із розміткою) міститься в тому самому PDF; як попередній перегляд показано лише першу. Документ записав 2 сторінки на 343 455 байтів. Виділіть заголовок у будь-якому переглядачі PDF, щоб переконатися, що це текст.

## Пам'ять, файли й скасування \{#files}
Запис малює сторінки **по одній**: зображення сторінки обчислюються безпосередньо перед її малюванням і вивільняються після, тож пам'ять містить растри однієї сторінки, а не всіх. `write(to:)` змушує Cairo писати у тимчасовий файл поруч із призначенням, який атомарно замінює призначення лише тоді, коли документ завершено; збій чи скасування лишає наявний файл як був. Малювання й файловий вивід виконуються поза кооперативним виконавцем Swift, а скасування завдання, що викликає операцію, зупиняє роботу з `CancellationError`. Батьківські каталоги не створюються.

## Помилки \{#errors}
<Example id="pdf.limits" />

| Ситуація | Результат |
| --- | --- |
| Власний розмір сторінки поза `1…14 400` пунктів | `invalidOption(name: "page width", …"from 1 to 14400 points")`, під час створення сторінки |
| Прямокутник без площі | `invalidOption(name: "rectangle", …)`, під час додавання |
| Прямокутник без заливки й обведення | `invalidOption`: «give a fill, a stroke, or both» |
| Хибна розмітка Pango | `invalidOption(name: "text", …"the Pango markup is not valid")`, під час додавання тексту |
| Документ без сторінок | `invalidInput`: «a document needs at least one page» |
| Конвеєр зображення, що завершується помилкою | помилка цього конвеєра з `data()` / `write(to:)` |
| Cairo не може створити PDF | `encode` |
